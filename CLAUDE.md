# Project notes

## Writing style
- Do **not** use the words "wild" or "wildly" anywhere (notebooks, markdown,
  comments, commit messages). Prefer alternatives like "dramatically",
  "very", "strikingly".
- Avoid aphoristic antithesis — the "not X; it's Y" negation-reframe
  construction (e.g. "Garbage in, garbage out is not a slogan; it is the
  mechanism", "X is a modeling decision, not cleanup") and punchy one-line
  epigrams generally. State the point directly with concrete information
  instead of a dramatic contrast.
- Every numbered section heading (`## 1. ...`, `## 2. ...`) is followed, in
  the same markdown cell, by a short "why use this function" explanation —
  one or two sentences on what the function does and why a data scientist
  reaches for it (e.g. "`pd.read_excel()` opens it the same way
  `pd.read_csv()` opens a CSV — you point it at a path and get back a
  DataFrame."). This replaced the earlier heading-only rule.
- Each notebook ends with a "Why this matters to a data scientist / AI
  engineer" section (before the Takeaway cell, which the generator hoists to
  the top) connecting the bias story to models and downstream pipelines.

## Structure
- Course material is organized one folder per day, e.g.
  `Data Cleaning and Exploratory Data Analysis/`, each containing its own
  `data/` and `notebooks/`.
- Notebooks are generated by `notebooks/_build_notebooks.py` within each day
  folder. Edit the generator, then re-run it — do not hand-edit the `.ipynb`
  files directly.
- Markdown cells are wrapped in an inline-styled large-font div (24px) by the
  generator so text is readable in any notebook renderer.
- Each notebook opens with a different pandas reader (read_csv, read_excel,
  read_json, read_parquet, read_feather, read_pickle, read_html); fall back to
  CSV if formats run out.
